# Escherize – specification

Automatic generation of tiles that tile the plane and resemble a given silhouette
(Escherization), for C#/.NET. The method is the exhaustive variant of the Koizumi–Sugihara
formulation as described in Nagata & Imahori, *An Efficient Algorithm for the Escherization
Problem in the Polygon Representation* (arXiv:1912.09605, 2019). References of the form
"[NI §x]" point into that paper.

---

## 0. Instructions

1. Read the whole document before starting. The paper is at https://arxiv.org/abs/1912.09605
   (download it yourself; it is not distributed with this repository).
2. Implement phase by phase in the order of §10. After each phase, `dotnet build` must give
   zero warnings and `dotnet test` must be green before moving on. One commit per phase.
3. Do not weaken tolerances, mark tests as `Skip`, or delete tests to make them pass. If a
   test reveals that the specification is wrong, stop, describe the finding in
   `DECISIONS.md`, and ask.
4. Two details are deliberately **not** fixed by this specification: the glide axis (X/Y)
   per glide pair, and the sign of the rotation angle θ. They are settled empirically by
   the validation test in §8.2, recorded in `DECISIONS.md`, and hard-coded thereafter.
5. No NuGet dependencies beyond the list in §2.
6. The innermost search loop (§6.3) must not allocate, must not use LINQ, and must not call
   virtual methods.
7. Public APIs carry XML documentation. Code comments and identifiers are written in
   English.

## 1. Goal and scope

**Goal:** given a closed silhouette (image, polygon, or country outline), find the tiles
that (a) tile the plane isohedrally and (b) come closest to the silhouette. The result is
the top K candidates for manual judgement, since the distance measure does not correspond
exactly to human recognition [NI, supplement].

**Intended use:** art and physical paving stones. Recognisability matters more than minimal
error, and physical producibility (no thin necks) is a criterion of its own.

**In scope for v1:**
- Input: PNG silhouette, polygon (JSON/CSV), GeoJSON (countries/regions).
- Preprocessing: contour, smoothing, resampling, normalisation, landmarks.
- Search: 9 general isohedral types × all distributions of interior points k × all start
  offsets j × both orientations.
- Post-processing: self-intersection filter, diversity filter, neck width, weighted
  reranking.
- Output: JSON, SVG (tile, tiling, contact sheet), DXF (tile outline in mm).

**Out of scope for v1:** GUI, U and I edges, tilings with several distinct tiles,
non-linear post-optimisation of the tile.

## 3. Conventions and data model

- All indices are 0-based. A polygon has n points indexed t = 0..n−1, and indices are read
  cyclically (mod n).
- **Coordinate vector** (length 2n): `u[t] = x_t`, `u[n + t] = y_t`. The same layout applies
  to the goal vector `w`.
- **Orientation:** the goal polygon is made positively oriented (counter-clockwise, signed
  area > 0 in y-up coordinates). Image coordinates have y downwards and must be mirrored
  (y ← −y) on import.
- **Normalisation:** subtract the point average and scale so that ‖w‖₂ = 1. Keep `centroid`
  and `scale` so the transform can be undone.
- **Tile template:** nv tiling vertices V₀..V_{nv−1} and nv edges in boundary order. Edge s
  runs from V_s to V_{(s+1) mod nv} and has k_s interior points.
  - h(0) = 0 and h(s+1) = h(s) + k_s + 1.
  - Vertex V_s sits at index h(s), and edge point i (i = 1..k_s) sits at index h(s) + i.
  - Notation: e_s(i) for i = 0..k_s+1, where e_s(0) = V_s and e_s(k_s+1) = V_{s+1}.
  - It must hold that n = nv + Σ_s k_s.

Central types (suggested; names may be adjusted):

```csharp
public enum EdgeKind { C, T, G, R }          // C = S edge (self, 180°), T = translation pair, G = glide pair, R = rotation pair
public enum GlideAxis { None, X, Y }

public sealed record EdgeSpec(EdgeKind Kind, int PairId, int KVar, GlideAxis Axis = GlideAxis.None, double ThetaDeg = 0);
public sealed record TemplateSpec(string Name, string Heesch, EdgeSpec[] Edges)
{
    public bool UsesProcrustes => Edges.Any(e => e.Kind == EdgeKind.G);
}

public readonly record struct CandidateKey(int TypeIndex, int[] K, int J, bool Reversed);
public sealed record Candidate(CandidateKey Key, double Error /* e, §6.1 */);
```

## 4. Preprocessing

### 4.1 PNG → contour (`Escherize.Imaging`)
1. Decode the image with StbImageSharp to RGBA.
2. Compute luminance L = 0.299R + 0.587G + 0.114B. Pixels with alpha < 128 count as
   background.
3. Threshold with Otsu by default (`--threshold <0..255>` overrides). The foreground is
   dark by default; `--invert` reverses this.
4. Keep the largest 8-connected foreground component and fill holes: flood fill the
   background from the image border, and treat everything not reached as foreground.
5. Run marching squares on the mask at iso value 0.5 and keep the longest closed loop (the
   outer boundary).
6. Mirror y and make the polygon positively oriented.

### 4.2 Polygon import
- JSON: `{ "points": [[x,y], ...] }`
- CSV: one `x,y` per line, with an optional header.
- Remove consecutive duplicates (distance < 1e-12 · diameter) and orient positively.

### 4.3 GeoJSON (countries)
- Support `Polygon`, `MultiPolygon`, `Feature` and `FeatureCollection` (the first feature,
  or `--feature-name`).
- Project every exterior ring with the **Lambert azimuthal equal-area projection**
  (spherical, R = 6371 km) centred on the bounding box centre (φ₁, λ₀):
  ```
  k' = sqrt(2 / (1 + sinφ₁ sinφ + cosφ₁ cosφ cos(λ−λ₀)))
  x  = R k' cosφ sin(λ−λ₀)
  y  = R k' (cosφ₁ sinφ − sinφ₁ cosφ cos(λ−λ₀))
  ```
- Choose the ring with the largest projected area (for Norway that is the mainland), or the
  ring given by `--ring-index`.

### 4.4 Smoothing
- Resample the contour to N_s = 2048 points at equal arc length.
- Take the DFT of zₖ = xₖ + i·yₖ (a direct sum is good enough) and keep the harmonics with
  |h| ≤ H. Then take the inverse DFT.
- `--smooth H` defaults to 24. `--smooth 0` disables smoothing.
- Alternative: `--dp <tolerance>` for Douglas–Peucker, read as a fraction of the diameter.

### 4.5 Resampling and normalisation
- Resample to n points at equal arc length (`--n`, default 64). The start point is contour
  index 0; the start point does not affect the result, because the j loop covers every
  offset.
- Normalise as in §3.
- Also build the reversed goal: `W_rev[t] = W[(n − t) mod n]`. It has the opposite
  orientation, and that is intended: mirror images of templates are covered by running the
  search on both W and W_rev (§7).

### 4.6 Landmarks and weights (used only in §7.4)
- A landmark has a position (in input coordinates), a weight W_l ≥ 1 and a width σ_l (a
  fraction of the perimeter, default 0.03).
- Project the position onto the nearest contour point, which gives the arc length parameter
  s_l ∈ [0,1).
- Point weight: `ω_t = 1 + Σ_l (W_l − 1) · exp(−d(s_t, s_l)² / (2σ_l²))`, where d is cyclic
  arc length distance.

## 5. Tile templates and parametrisation

### 5.1 Edge relations
All relations are linear in the point coordinates. For a pair (a, b) both edges share the
same k.

| Type | Relation (i = 0..k+1 unless stated) | Neighbour isometry g across edge a (b: g⁻¹) |
|---|---|---|
| **C** (self) | e(i) + e(k+1−i) = V_s + V_{s+1}, for i = 1..⌊k/2⌋. For odd k the middle point e((k+1)/2) equals the midpoint of the edge. | g(x) = V_s + V_{s+1} − x |
| **T** (a,b) | b(i) − b(0) = a(k+1−i) − a(k+1) | g(x) = x + a(k+1) − b(0) |
| **G** (a,b), axis | b(i) − b(0) = F·(a(i) − a(0)), where F_X = diag(1,−1) and F_Y = diag(−1,1) | g(x) = a(0) + F·(x − b(0)) |
| **R** (a,b), b = a+1, V = a(k+1) = b(0) | b(i) − V = R(θ)·(a(k+1−i) − V) | g(x) = V + R(−θ)·(x − V) |

The relation for i = k+1 gives the **corner conditions**:
- T: b(k+1) − b(0) = a(0) − a(k+1)
- G: b(k+1) − b(0) = F·(a(k+1) − a(0))
- R: b(k+1) − V = R(θ)·(a(0) − V)
- C: none

### 5.2 Template table: the nine general types [NI fig. 4]
The edges are listed in boundary order. Pairs are identified by `PairId` (A, B, C), and
`KVar` says which k variable the edge uses.

| Name | Heesch | Edges (Kind(PairId, KVar)) | Metric |
|---|---|---|---|
| IH1 | TTTTTT | T(A,0) T(B,1) T(C,2) T(A,0) T(B,1) T(C,2) | Euclid |
| IH2 | TG1G1TG2G2 | T(A,0) G(B,1) G(B,1) T(A,0) G(C,2) G(C,2) | Procrustes |
| IH3 | TG1G2TG2G1 | T(A,0) G(B,1) G(C,2) T(A,0) G(C,2) G(B,1) | Procrustes |
| IH4 | TCCTCC | T(A,0) C(1) C(2) T(A,0) C(3) C(4) | Euclid |
| IH5 | TCCTGG | T(A,0) G(B,1) G(B,1) T(A,0) C(2) C(3) | Procrustes |
| IH6 | CG1CG2G1G2 | G(A,0) G(B,1) G(A,0) C(2) G(B,1) C(3) | Procrustes |
| IH7 | C3C3C3C3C3C3 | R(A,0,120°) R(A,0,120°) R(B,1,120°) R(B,1,120°) R(C,2,120°) R(C,2,120°) | Euclid |
| IH21 | CC3C3C6C6 | C(0) R(A,1,120°) R(A,1,120°) R(B,2,60°) R(B,2,60°) | Euclid |
| IH28 | CC4C4C4C4 | C(0) R(A,1,90°) R(A,1,90°) R(B,2,90°) R(B,2,90°) | Euclid |

- **Glide axes:** unknown per G pair. Try every combination in {X,Y}^(number of G pairs) in
  §8.2.
- **Sign of θ:** try all-positive and all-negative in §8.2.
- Whichever configuration or configurations pass are hard-coded into the template table and
  recorded in `DECISIONS.md`.

### 5.3 Vertex parametrisation B_v
- Unknowns: u_v (2nv), with the same x/y block layout as in §3.
- Build A_v from the corner conditions in §5.1. Find the null space by Gaussian elimination
  with full pivoting to reduced row echelon form (tolerance 1e-12), and orthonormalise with
  two-pass modified Gram–Schmidt (MGS2).
- The result is B_v (2nv × md). The rows d_s = B_v[s,:] and d_{nv+s} = B_v[nv+s,:]
  parametrise x and y for vertex s.
- Assert md ≥ 3. Record md per type in `DECISIONS.md`.

### 5.4 Edge parameters B_s (sparse, orthonormal columns)
A **run** is all the interior point pairs (p(i), q(i)) of one relation, where i = 1..k, or
i = 1..⌊k/2⌋ for C. Each run gives two columns (an x column and a y column).

The columns are expressed as linear forms L over z = (x_p, y_p, x_q, y_q). All coefficients
below are before scaling by 1/√2.

| Run | p(i) | q(i) | L_x | L_y |
|---|---|---|---|---|
| C | h(s)+i | h(s)+k+1−i | (1,0,−1,0) | (0,1,0,−1) |
| T | h(a)+i | h(b)+k+1−i | (1,0,1,0) | (0,1,0,1) |
| G, X | h(a)+i | h(b)+i | (1,0,1,0) | (0,1,0,−1) |
| G, Y | h(a)+i | h(b)+i | (1,0,−1,0) | (0,1,0,1) |
| R(θ) | h(a)+k+1−i | h(b)+i | (1,0,cosθ,sinθ) | (0,1,−sinθ,cosθ) |

- A run is **anti-diagonal** when p and q travel in opposite directions (C, T, R) and
  **diagonal** when they travel in the same direction (G).
- The columns are orthonormal because no two columns share a non-zero row. Each column has
  norm 1 and L_x ⟂ L_y.

### 5.5 Vertex part B_d → B'_d → B''_d [NI §3.3]
1. **Basis rows B_d** (2n × md), expressing every point linearly in terms of the vertices:
   - Vertex V_s: row d_s (x) and d_{nv+s} (y).
   - T run: p has basis a(0), and q has basis b(k+1).
   - G run: p has basis a(0), and q has basis b(0).
   - R run: both p and q have basis V.
   - C run and C midpoint: basis ½(V_s + V_{s+1}).
2. **Project out B_s:** for each run, the four coordinate rows (x_p, y_p, x_q, y_q) form a
   block X (4 × md). Compute `X' = (I − P)X` with `P = ½(L_x L_xᵀ + L_y L_yᵀ)`. The result
   is constant along the run. Vertex rows and the C midpoint are unchanged.
3. **Gram matrix:** `Gm = B'_dᵀ B'_d = Σ_vertices (d dᵀ) + Σ_runs len · X'ᵀX' + Σ_midpoints (r rᵀ)`.
   Factorise with Cholesky: `Gm = LLᵀ`. Gm ≥ I because the vertex rows alone are
   orthonormal, so the factorisation is well conditioned.
4. Compute `B''_d = B'_d L⁻ᵀ`. Then `B = [B''_d | B_s]` is orthonormal (2n × m, where
   m = md + ms).

The **dense builder** (phase F3) materialises B explicitly. The **fast evaluator**
(phase F4) uses only the run description, Gm and L.

### 5.6 Enumeration of k
- For a template with v k variables and multiplicities m_v (2 for a pair, 1 for C) it must
  hold that `Σ m_v k_v = n − nv` with k_v ≥ 0.
- Enumerate iteratively in lexicographic order. The order must be deterministic.
- `--min-k` (default 0) gives a lower bound per edge.
- Print the number of combinations per type before the search starts, so that progress can
  be shown.

## 6. Evaluation

### 6.1 Distance measure [NI §3.4, eq. 39–41]
The goal vector w_j is the goal shifted so that goal[(t + j) mod n] lands on template index
t. With ‖w‖ = 1:

- **Euclid** (templates without G): `e = ‖w‖² − ‖Bᵀw‖²`
- **Procrustes** (templates with G, where the rotation is free and the scale is fixed):
  ```
  w_c = (y, −x)                       // w rotated by −90°
  p = Bᵀw,  p_c = Bᵀw_c
  Gm2 = [[p·p, p·p_c], [p·p_c, p_c·p_c]]
  λ = (g11+g22)/2 + sqrt(((g11−g22)/2)² + g12²)
  e = ‖w‖² − λ
  ```

Properties:
- Both measures are ≥ 0 and are comparable across types.
- √e is the relative RMS deviation. Report both e and √e as a percentage.

### 6.2 Dense evaluator (phase F3)
Use explicit B and compute directly per §6.1. This evaluator is used for reconstruction,
weighted reranking, and as the reference in tests.

### 6.3 Fast evaluator (phase F4): O(1) in n per (k, j)
Precompute tables once per goal orientation (W and W_rev). Use doubled arrays X[0..2n) and
Y[0..2n) with X[i] = x_{i mod n}.

- **1D prefix:** S_x, S_y, S_xx, S_yy and S_xy, each of length 2n+1.
- **Anti-diagonal:** `ANTI_fg[s][m] = Σ_{i<m} f(i)·g((s−i) mod n)` for s ∈ [0,n),
  m ∈ [0,2n] and fg ∈ {xx, xy, yx, yy}.
- **Diagonal:** `DIAG_fg[d][m] = Σ_{i<m} f(i)·g((i+d) mod n)`.
- Memory use is roughly 8 · n · (2n+1) · 8 B per orientation, which is 1.9 MB for n = 120.

Per (k, j):

1. **Run moments.** For each run with absolute start P = p(1)+j, Q = q(1)+j and length ℓ:
   build the moment matrix `M = Σ_i z_i z_iᵀ` (4 × 4). The pp and qq blocks come from the 1D
   prefix. The pq block comes from ANTI (s = (P+Q) mod n) or DIAG (d = (Q−P) mod n) as
   differences `T[·][P+ℓ] − T[·][P]`. For a run with descending q, normalise so that p is
   the ascending index. Take care that P+ℓ ≤ 2n.
2. **Vertex part.** `g = B'_dᵀ w = Σ_vertices (d_x x_v + d_y y_v) + Σ_runs X'ᵀ·(ΣX_p, ΣY_p, ΣX_q, ΣY_q) + midpoints`.
   Then solve `c = L⁻¹ g`. For Procrustes, do the same for w_c, giving c_c; the sums are
   reused via w_c = (y, −x).
3. **Edge part.** With `L̂ = L/√2`, `s_ww = Σ_runs Σ_{L∈{L_x,L_y}} L̂ᵀ M L̂`. Procrustes also
   needs `s_wwc = Σ L̂ᵀ M (Jᵀ L̂)` and `s_wcwc = Σ (JᵀL̂)ᵀ M (JᵀL̂)`, where J maps
   z → (y_p, −x_p, y_q, −x_q).
4. **Result:** `‖p‖² = ‖c‖² + s_ww`, `p·p_c = c·c_c + s_wwc` and
   `‖p_c‖² = ‖c_c‖² + s_wcwc`. Substitute into §6.1.

The per-k setup is done once per k: run layout, X' blocks, Gm and Cholesky.

### 6.4 Tile reconstruction
Use the dense builder for (type, k, j, rev):
- **Euclid:** ξ* = Bᵀw_j.
- **Procrustes:** ξ* = [p p_c]·v, where v is the unit eigenvector of Gm2 for λ. Then
  ‖ξ*‖ = √λ.
- u* = Bξ*. For the overlay, compute the optimal rotation
  θ* = atan2(Σ(x_u y_w − y_u x_w), Σ(x_u x_w + y_u y_w)).
- Store the tile in template order together with h(s), the edge metadata, and the mapping
  from template index t to goal index (t+j) mod n (via W_rev when rev = true).
- Denormalise to input units with `scale` and `centroid`.

## 7. Search

### 7.1 Loop structure
```
for rev in {false, true}:
  for type in selectedTypes:
    parallel over k vectors (Partitioner, chunk ~ 64 k vectors):
      setup per k (§6.3)
      for j in 0..n−1:
        e = Eval(k, j)
        thread-local topK.Offer(e, key)
merge heaps → sort deterministically
```
- **Sort key:** (e, typeIndex, k lexicographically, j, rev). The result must be identical
  regardless of the number of threads.
- `--threads` defaults to `Environment.ProcessorCount`.
- Support `CancellationToken` and `IProgress<double>`.

### 7.2 Raw candidates
- Keep `K_raw = max(10·K, 200)` candidates, where K = `--top` (default 20).
- Filter with a **margin of ≤ 1e-12**: candidates sharing a key are not removed, but
  candidates with an identical reconstructed tile (§7.3) count as duplicates.

### 7.3 Post-processing (in order)
1. Reconstruct the tile (§6.4).
2. **Self-intersection:** O(n²) segment test for non-adjacent segments. A touch within
   1e-9 · diameter counts as a crossing. Also discard tiles with negative signed area.
3. **Neck width:** the smallest distance between a point and a segment whose cyclic index
   distance is ≥ n/10. Report the value relative to √area. `--min-neck <fraction>` discards
   candidates below the bound (off by default).
4. **Diversity:** discard a candidate if the Procrustes distance (rotation + scale) to an
   already selected tile is < δ (`--diversity`, default 0.02). Tiles are compared pointwise
   in goal index order.
5. Keep the best K.

### 7.4 Weighted reranking (when landmarks are given)
- For each of the `K_raw` raw candidates: build `B̃ = Ω^{1/2}B` and orthonormalise with
  dense QR or MGS2.
- Set `w̃ = Ω^{1/2}w`. The point weight acts isotropically per point, so rotation commutes
  with Ω, and the formulas in §6.1 apply unchanged to (B̃, w̃).
- Rank by the weighted e and then run §7.3. Report both the weighted and the unweighted
  error.

### 7.5 Pruning (phase F6, optional)
Implement the decomposition relaxation [NI §4] for IH4, IH5 and IH6 **only if the
performance targets in §12 are not met**. The bound is the K_raw-th best error so far.

## 8. Validation and tests

### 8.1 Geometry and import
- Resampling: equal arc length within 1e-9.
- Orientation: signed area > 0 after import.
- Smoothing: a circle is unchanged within 1e-6. A square with H = 8 has its area within
  ±5 %.
- PNG: a synthetic circle with r = 100 px (generated in the test) gives a contour whose area
  is within 1 % of πr².
- LAEA: the projection centre maps to (0,0), and two points symmetric about λ₀ give mirror
  symmetric x.

### 8.2 Template validity (critical; settles the glide axes and the sign of θ)
For each type and each configuration (axes and signs):

1. Build a goal with 36 points (a circle with seeded noise) and pick a random k vector where
   every k ≥ 2.
2. Compute `u = B(Bᵀw) + 0.05·B·r`, where r is normally distributed with a fixed seed. Draw
   again on self-intersection (at most 50 attempts).
3. **Edge coverage:** for each edge e, g_e must map the partner edge's points onto edge e's
   points within 1e-9.
4. **Tiling:** build a patch by BFS to depth 3 via the isometries (§9.3). Sample 20 000
   seeded points in a disc of radius 2·R_tile around the base tile's centroid. Every point
   further than 1e-6 · diameter from all boundaries must lie in **exactly one** tile. Use
   point-in-polygon with the winding number.
5. Exactly the equivalent correct configurations must pass. At least one wrong configuration
   must fail, otherwise the test is too weak.

Once `DECISIONS.md` has been filled in: the test runs the hard-coded configuration for all
9 types with 20 seeds each.

### 8.3 Parametrisation
- BᵀB = I within 1e-10.
- A·(Bξ) = 0 for random ξ, where A is built from **all** the relations in §5.1 (including
  the interior points).
- rank(B) = nullity(A), where the nullity is computed with a MathNet SVD (tolerance 1e-9).

### 8.4 Oracle
For each type: 50 random (goal, k, j, rev).
- The oracle builds B from an SVD of the null space of A and computes λ with MathNet's
  symmetric eigenvalue solver on BᵀVB [NI eq. 9–10].
- Requirement: |e_fast − e_dense| ≤ 1e-9 and |e_dense − e_oracle| ≤ 1e-9.

### 8.5 Invariance
- e is unchanged when the goal is rotated (for every type) and when it is translated.
- e for rev=false on W equals e for rev=true on W_rev.

### 8.6 Known answer
When the goal is itself a valid tile generated from (type, k, ξ), a full search must give
e < 1e-10 at rank 1.

### 8.7 Determinism and regression
- The same input with `--threads 1` and `--threads 8` gives a byte-identical `summary.json`.
- A snapshot of the top 5 (type, k, j, rev, e rounded to 1e-9) for four fixed test shapes in
  `tests/fixtures`:
  - a star
  - an L shape
  - an elongated shape with a narrow waist (Norway-like)
  - a cat-like shape

```
rank01_IH4_tile.svg             # edges coloured per pair, vertices as dots, goal dashed grey
rank01_IH4_tiling.svg           # patch of 30–80 tiles, 4–6 colours, clipped to a rectangle
rank01_IH4_tile.dxf             # closed outline in mm
...
```
- `--render-top N` decides how many candidates get their own files (default 5).
- Every candidate in the top K is stored in the JSON.

### 9.2 `summary.json`
```json
{
  "input": { "path": "norway.geojson", "n": 64, "smooth": 24, "centroid": [0,0], "scale": 1.0 },
  "search": { "types": ["IH1","IH2","IH3","IH4","IH5","IH6","IH7","IH21","IH28"], "evaluations": 0, "seconds": 0.0 },
  "candidates": [
    {
      "rank": 1, "type": "IH4", "heesch": "TCCTCC", "k": [5,9,11,8,14], "j": 17, "reversed": false,
      "error": 0.0123, "rmsPercent": 11.1, "weightedError": null, "neckWidthRel": 0.18,
      "vertices": [0, 6, 16, 28, 34, 43],
      "tile": [[x,y], ...],
      "edges": [{ "kind": "T", "pair": "A", "from": 0, "to": 6 }],
      "isometries": [{ "edge": 0, "m": [a,b,c,d,tx,ty] }]
    }
  ]
}
```

### 9.3 Tiling generator
- Isometries are represented as affine 2×3 matrices in double.
- BFS starts from the identity. The neighbour of a placed tile M across edge e is M ∘ g_e.
- Deduplicate on the quantised centroid (1e-6 · diameter).
- Stop when every tile intersecting the target rectangle has been placed, or at 400 tiles.
- Colours: greedy colouring in BFS order, where adjacency means a shared edge. The palette
  holds 6 muted colours.

### 9.4 DXF
- ASCII DXF R12 with `POLYLINE`/`VERTEX`/`SEQEND` and the closed flag 1, one tile per file,
  layer `TILE`.
- Scale so that the longest side of the bounding box becomes `--tile-size-mm` (default 200).
- Include `$INSUNITS = 4` (mm) in the header.

## 11. CLI

```
escherize preprocess --input <file> [--n 64] [--smooth 24|--dp 0.005] [--invert] [--threshold T]
                     [--ring-index i] [--out dir]
escherize run        --input <file> | --config job.json
                     [--n 64] [--types IH4,IH5,IH6|all] [--top 20] [--render-top 5]
                     [--min-k 0] [--diversity 0.02] [--min-neck 0.0] [--threads N]
                     [--landmarks lm.json] [--tile-size-mm 200] [--out dir]
escherize render     --result summary.json --rank 3 [--tiles 80] [--out dir]
```

- Exit codes: 0 on success, 1 on invalid input, 2 on an internal error. Error messages go to
  stderr.
- `job.json` holds the same fields as the CLI flags (camelCase). CLI flags override the file.

`lm.json`:
```json
{ "landmarks": [ { "name": "Nordkapp", "x": 25.78, "y": 71.17, "weight": 4, "sigma": 0.03 } ] }
```
For GeoJSON input, x/y are longitude and latitude and are projected the same way as the
contour.
